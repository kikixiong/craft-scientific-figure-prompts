# Worked example: adapting a two-phase reference

Use this example to understand the format, not as content to copy.

## Learned visual grammar

- Two independent dashed phase containers.
- Two stacked panels per phase.
- A narrow shared-contract bridge across the seam.
- Parallel lanes on the execution side.
- Pastel semantic colors, compact sticker-like icons, and short labels.
- Global constraints followed by panel-local instructions and a final audit.

## Scientific content contract

Hypothetical paper:

- Must show: labelled measurements → graph model → calibrated interval →
  three fixed-input evaluation arms.
- Must not imply: node score equals item truth.
- Baseline result: verified negative gate.
- End-task metrics: pending.
- Shared: candidate pool and budget.
- Separate: ordered context and generated output.

## Abbreviated production prompt

```text
Use case: scientific-educational
Asset type: publication-quality paper overview
Primary request: Show how a source-level measurement becomes a graph signal
and then changes evidence ordering under a controlled evaluation.

INPUT ROLES
Image 1: style reference only.
Use its two-phase silhouette, seam bridge, pastel semantic palette, rounded
tabs, and compact icon language.
Ignore and prohibit its original labels, topic, agents, and screenshot prose.

SCIENTIFIC CONTENT CONTRACT — HIGHEST PRIORITY
Must show:
- labelled measurement → graph extension → point and interval signals;
- shared fixed candidate pool;
- "Base", "Point", and "Conservative" lanes;
- separate contexts and outputs;
- one verified failed gate;
- end-task outputs marked "PENDING".
Must not imply:
- graph score equals item truth;
- a pending outcome is successful;
- separate arms reuse one generation.

CANVAS AND BACKGROUND
Use a 4:3 landscape composition target on uniform pure white. No paper,
dashboard, poster, texture, vignette, or global gradient.

VISUAL STRUCTURE
Use two adjacent dashed phase containers. Stack two panels in each phase.
Place a three-module shared-contract bridge across the seam. Use parallel lanes
in the upper-right panel.

TYPOGRAPHY AND EXACT TEXT
Use a rounded handwritten academic display face, a plain compact label face,
and monospaced technical tokens.
Render verbatim: "Base", "Point", "Conservative", "PENDING", "failed gate".

COLOR AND ICON LANGUAGE
Orange = measurement or intervention.
Green = uncertainty or diagnostics.
Gray = shared infrastructure.
Blue = data.
Yellow = pending.
Red = failed gate.
Never use green success marks on pending outputs.

PANEL A — Measurement & Graph Extension
Show rating cards feeding a node-link graph and then point/interval heads.
Add "scoreability ≠ validity".

PANEL B — Calibration Boundary
Show interval calibration and one red "failed gate" audit row.

CENTRAL BRIDGE — Shared Contracts
Show mapping, signal status, and frozen protocol as three stacked modules.

PANEL C — Fixed-Pool Evaluation Arms
Feed one shared candidate pool into "Base", "Point", and "Conservative".
End each lane with its own context card.

PANEL D — Independent Outputs
Show one request, response, and evaluator output per lane. Mark all end-task
cards "PENDING" in yellow.

ARROW AND LINE RULES
Use orange for intervention, green for uncertainty, and gray for shared flow.
Every arrow must terminate on a real object. Avoid crossings.

VISUAL DENSITY AND LEGIBILITY
Keep labels to one to five words. Maintain compact conference-figure density
without overlaps or tiny prose.

STRICT NEGATIVE CONSTRAINTS
Do not copy reference labels, invent a fourth arm, merge arm outputs, add
scores or winners, turn the failed gate green, tint the canvas, add 3D effects,
use corporate-dashboard styling, or add a watermark.

FINAL VALIDATION
Verify two phase borders, the seam bridge, three separate lanes, exact text,
one red failed gate, yellow pending outputs, and pure-white negative space.
```
